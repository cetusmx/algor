## Overview

**Page Purpose:** Proveer validación técnica profunda. Demostrar la capacidad de ejecución arquitectónica y los resultados conseguidos en un escenario idéntico al problema del usuario.

**Entry Points:**
- Clic en una tarjeta de la grilla de Casos de Uso (01.2).

**User Mental State:**
Interés y escepticismo técnico. Busca indicios de que la agencia sabe de lo que habla y no es "vendehumos". Evaluará las herramientas y la arquitectura usadas.

**Main User Goal:** Validar técnicamente el éxito de algor y confirmar que este equipo es capaz de resolver su urgencia operativa.

**Business Goal:** Convencer al usuario y llevarlo al flujo de contacto/agendamiento.

**URL/Route:** `/casos-de-uso/integracion-aspel-legacy` (dinámico)

## Design Sections

### 1. Global Navigation (Header)
- Igual a 01.1

### 2. Case Study Header
- **Role:** Resumen ejecutivo técnico.
- **Content:**
  - H1: "Extracción en tiempo real de Aspel hacia ecosistema moderno sin downtime."
  - Metadata: Cliente (opcional/industria), Duración del proyecto, Stack Tecnológico utilizado (Python, SQL Server, AWS, etc.).

### 3. The Challenge (El Reto)
- **Role:** Empatizar con el dolor (que es el mismo del usuario).
- **Content:** Explicación del sistema cerrado, la imposibilidad de reporteo en tiempo real y los riesgos operativos.

### 4. The Solution Architecture (La Arquitectura)
- **Role:** El núcleo de la validación técnica.
- **Content:** 
  - Diagrama de arquitectura de la solución (ej. extracción cronometrada, colas de mensajes, API intermediaria).
  - Texto detallado pero conciso explicando la decisión arquitectónica.
- **Visuals:** Diagramas puros estilo C4 Model, topologías de red AWS o Mermaid limpios. Nada de isométricos ni ilustraciones flat; estética de documentación técnica dura ("ingenieros aburridos pero efectivos").

### 5. Results & Metrics (El Impacto)
- **Role:** Evidenciar que la solución funciona.
- **Content:** "0 incidentes en producción", "Sincronización en < 5 segundos", etc.

### 6. Conversion CTA (Bottom)
- **Role:** Capitalizar el interés generado.
- **Content:** 
  - H2: "¿Tienes un desafío similar de integración?"
  - Botón: "Agendar Consulta Técnica" (lleva a 01.4).

### 7. Global Footer
- Igual a 01.1

## Phase 4: UI Specifications & Component Mapping

### Global Layout & Theming
- **Aesthetic:** "Ingenieros efectivos". High-contrast, brutalist-lite tech documentation style.
- **Background:** `#0f172a` (Dark Slate).
- **Typography:** Inter for body, JetBrains Mono for metrics and architecture diagrams.

### 2. Case Study Header
- **Layout:** Breadcrumb navigation top left (`Casos de Uso / Integración Legacy`).
- **Typography:** `H1` massive (`text-4xl md:text-6xl font-bold tracking-tight`).
- **Metadata Flexbox:** `flex flex-wrap gap-4 mt-6 text-slate-400 font-mono text-sm`.

### 4. The Solution Architecture
- **Component:** `ArchitectureDiagram` (puede ser imagen SVG pura o componente interactivo).
- **Visuals:** Wireframe aesthetic, white/gray outlines on the dark background, bright orange (`#f97316`) for data flow lines.

### 5. Results & Metrics
- **Component:** `MetricCard`
- **Layout:** `grid grid-cols-1 md:grid-cols-3 gap-6 my-12`.
- **Visuals:** Grandes números tipográficos (ej. `text-5xl text-orange-400 font-mono`) con la descripción abajo. Borde sutil.
