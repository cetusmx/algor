- (decision) Stack: React (Vite) for frontend, Express (Node.js) for backend, serving static Vite build. SQLite for database. Ensures single-container architecture.
- (constraint) Deployment target is a Linux VPS running multiple domains via an NGINX reverse proxy. Container must expose a single internal port. SQLite persistence volume must be mapped to the Linux host.
- (decision) Database access: Raw SQL instead of ORM, due to small project footprint.
- (decision) Network configuration: The single Docker container exposes only one internal port (3030). The Express backend serves both the API routes and the statically compiled Vite frontend on this same port, keeping the monolith clean.
- (decision) CI/CD Orchestrator: GitHub Actions. Binds workflow automation to the GitHub ecosystem.
- (decision) Build & Registry: Docker images are built within the GitHub Actions runner and pushed to GitHub Container Registry (GHCR). Prevents resource exhaustion on the target VPS by delegating build steps to CI.
- (decision) Deployment Access: Remote execution on the target VPS via SSH, using credentials stored securely in GitHub Secrets.
- (decision) Deployment Strategy: Replace-in-place. The existing container is stopped, pulled, and replaced with the new image. Accepted brief downtime prevents the operational complexity of a zero-downtime (Blue-Green) setup.
