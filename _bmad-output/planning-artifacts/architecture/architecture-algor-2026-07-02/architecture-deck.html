Arquitectura: algor B2B

Diseño técnico para la plataforma de captación de leads estructurada bajo un Monolito de Contenedor Único.

1. El Paradigma de Diseño

La aplicación está diseñada bajo el paradigma de Monolito de Contenedor Único (Single-Container Monolith). Esto garantiza un 100% de portabilidad, permitiendo que la aplicación (frontend, backend y base de datos) se levante con un simple comando de Docker en cualquier entorno.

2. Reflexión Técnica: Un Contenedor, Un Puerto

¿Por qué el contenedor expone solo el puerto 3030 en lugar de separar Front (8082) y Back (3030)?

En el desarrollo local, es común tener dos servidores corriendo (Vite para React y Node para Express). Sin embargo, llevar eso a producción dentro de un mismo contenedor Docker fuerza el uso de gestores de procesos internos (como supervisord), lo cual es un anti-patrón de contenedores.

La solución elegante y de grado de producción es compilar React en archivos estáticos puros (HTML/JS/CSS). Luego, configuramos a Node.js (Express) para que escuche en un solo puerto (3030). Express se encarga de interceptar las llamadas a la API (/api/*) para interactuar con la base de datos, y para cualquier otra ruta, simplemente entrega los archivos estáticos de React.

El VPS host utiliza NGINX como Proxy Inverso para recibir el tráfico de los distintos dominios, y simplemente enruta el tráfico web de algor.com directamente a nuestro contenedor en el puerto 3030. Un flujo limpio y sin fricciones internas.

3. Stack Tecnológico

  • React.js (Vite)
  • Node.js (Express)
  • SQLite (Raw SQL)
  • Docker
  • NGINX (Host)
